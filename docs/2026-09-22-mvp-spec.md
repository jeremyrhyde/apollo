---

## 1. Goal

A self-hosted personal app for **tracking** two things and seeing them on a
calendar:

1. **Workouts** — start a workout, add exercises from a configured catalog,
   log sets whose fields depend on the exercise (weight/reps, distance/time,
   time), finish it, and browse past workouts.
2. **Self-care — Skincare (Face)** — log which skincare types were done on a
   day, see what is due or overdue, and browse past sessions.

The **Calendar** is the landing page: week, month and year views showing when
each was done, with click-through into any session.

Used primarily from an **iPhone in Safari** at `http://<server>:8000/ui/`,
also from desktop. Single user, home network, no authentication (like Hermes
and Hestia).

### Success criteria

- Log a full gym workout on a phone without friction: pick exercises, sets
  prefilled from last time, adjust, ✓, finish.
- Log a skincare session in a few taps; see at a glance what's overdue.
- Open the app and immediately see, on the calendar, when each was last done.
- All tracking logic lives in the backend, stored so that later stats
  (strength growth, distance totals, per-type skincare frequency) and Claude
  recommendations are queries over existing data, not migrations.

### Non-goals (MVP)

Stats and PR calculation · Claude integration · workout templates · rest
timer · RPE / warmup / drop sets / supersets · skincare step checklists,
fixed schedules, skips, streaks · import/export · notifications · offline
mode · authentication · migrating Hermes or Hestia.

## 2. Architecture

- **Backend:** FastAPI + SQLite (aiosqlite), Python ≥ 3.11, `uv`. Follows the
  Hermes/Hestia patterns: `config.py` Settings, `core/` framework,
  forward-only migrations, EventBus.
- **Frontend:** **Svelte 5 + Vite + TypeScript** single-page app, built to
  `frontend/dist/` and served by FastAPI at `/ui/`. Chosen over the siblings'
  no-build Alpine for reusable components (one Calendar used in several
  places), built-in transitions, and a path to a future unified frontend for
  Hermes/Hestia/Apollo.
- **API** under `/api/…`; UI at `/ui/`. (Deviation from the siblings'
  root-level routes: one proxy prefix in dev, clean separation if the apps
  are ever combined.)
- **Principle:** the frontend displays and collects input; everything that
  computes, stores or decides lives in the backend.

## 3. Configuration

Three YAML files in `config/`, **committed** (they are the catalog, not
secrets). Validated strictly at startup by pydantic models in
`schemas/config.py`: unknown keys, duplicate keys, an exercise whose `type`
or `group` is undefined, or a malformed value fail with a message naming the
file and entry. The server still boots; errors are listed at `/api/health`,
and the affected area of the UI shows "config error — see Settings". Config is
read at startup; edits take effect on restart.

### `config/apollo.yaml`

```yaml
timezone: America/Los_Angeles     # IANA; all local-date decisions
day_start_hour: 4                 # a session before 04:00 belongs to the previous day
colors:                           # per-kind colors → CSS tokens
  workout:  "#4ade80"
  selfcare: "#60a5fa"
settings_defaults:                # seed the preferences table on first run only
  calendar_view: month            # week | month | year
  week_start: monday              # monday | sunday
  weight_unit: lb                 # lb | kg
  distance_unit: mi               # mi | km
  history_range: 1M               # 1W | 1M | 1Y
stale_workout_hours: 12           # open workout older than this prompts finish/discard
```

Kind colors must be distinguishable for common colour-vision deficiencies and
readable on both themes; defaults are chosen with that in mind.

### `config/exercises.yaml`

```yaml
metric_types:
  weight_reps:   { fields: [weight, reps] }
  reps:          { fields: [reps] }
  time:          { fields: [duration] }
  distance_time: { fields: [distance, duration] }
muscle_groups: [chest, back, shoulders, biceps, triceps, legs, glutes, core, cardio]
exercises:
  - { key: bench_press, name: Bench Press,   group: chest,  type: weight_reps }
  - { key: squat,       name: Back Squat,    groups: [legs, glutes], type: weight_reps }
  - { key: pull_up,     name: Pull-up,       group: back,   type: reps }
  - { key: run,         name: Run,           group: cardio, type: distance_time }
  - { key: stair_climb, name: Stair Climber, group: cardio, type: distance_time }
  - { key: plank,       name: Plank,         group: core,   type: time }
```

- **Fields** are a fixed built-in set: `weight`, `reps`, `distance`,
  `duration`. Each has a storage unit, display unit(s) and input widget.
  Adding a new field is a code change.
- Every exercise is logged as a list of **sets**; "sets" is not a field.
- `key` is permanent and identifies history. `name` may change freely.
- Exactly one of `group` or `groups` per exercise; each must be in
  `muscle_groups`.
- Removing an exercise hides it from the picker; its history remains.
- The shipped file contains a starter catalog of common exercises.

### `config/selfcare.yaml`

```yaml
categories:
  - key: skincare
    name: Skincare (Face)
    types:
      - { key: am_routine,  name: AM routine,  every_days: 1 }
      - { key: pm_routine,  name: PM routine,  every_days: 1 }
      - { key: exfoliation, name: Exfoliation, every_days: 7 }
      - { key: face_mask,   name: Face mask,   every_days: 7 }
      - { key: retinoid,    name: Retinoid,    every_days: 3 }
```

- One category in the MVP; more (hair, nails…) are config-only additions.
- `every_days` is optional (positive integer). Types without it are tracked
  but never "due".

## 4. Data model (SQLite)

Conventions: timestamps are UTC ISO-8601 text; `local_date` is `YYYY-MM-DD`
computed by `clock.py`; measurements are stored in SI units (kg, m, s);
names are snapshotted at log time so history survives catalog edits;
nothing derived (focus, last done, due, PRs, totals) is stored.

```sql
CREATE TABLE workout (
  id          INTEGER PRIMARY KEY,
  started_at  TEXT NOT NULL,
  ended_at    TEXT,                 -- NULL = open
  local_date  TEXT NOT NULL,
  notes       TEXT,
  created_at  TEXT NOT NULL,
  updated_at  TEXT NOT NULL
);
CREATE UNIQUE INDEX ux_workout_one_open ON workout((1)) WHERE ended_at IS NULL;
CREATE INDEX ix_workout_date ON workout(local_date);

CREATE TABLE workout_exercise (
  id            INTEGER PRIMARY KEY,
  workout_id    INTEGER NOT NULL REFERENCES workout(id) ON DELETE CASCADE,
  position      INTEGER NOT NULL,
  exercise_key  TEXT NOT NULL,
  exercise_name TEXT NOT NULL,      -- snapshot
  metric_type   TEXT NOT NULL,      -- snapshot
  planned       INTEGER NOT NULL DEFAULT 0,  -- 1 = created by a plan, not the user
  notes         TEXT
);
CREATE INDEX ix_we_key ON workout_exercise(exercise_key);

CREATE TABLE workout_exercise_group (
  workout_exercise_id INTEGER NOT NULL REFERENCES workout_exercise(id) ON DELETE CASCADE,
  muscle_group        TEXT NOT NULL,  -- snapshot
  PRIMARY KEY (workout_exercise_id, muscle_group)
);
CREATE INDEX ix_weg_group ON workout_exercise_group(muscle_group);

CREATE TABLE workout_set (
  id                  INTEGER PRIMARY KEY,
  workout_exercise_id INTEGER NOT NULL REFERENCES workout_exercise(id) ON DELETE CASCADE,
  position            INTEGER NOT NULL,
  done                INTEGER NOT NULL DEFAULT 0,
  weight_kg           REAL,
  reps                INTEGER,
  distance_m          REAL,
  duration_s          INTEGER,
  updated_at          TEXT NOT NULL
);
-- NULL = field not applicable to this set's metric type

CREATE TABLE selfcare_session (
  id           INTEGER PRIMARY KEY,
  category_key TEXT NOT NULL,
  performed_at TEXT NOT NULL,
  local_date   TEXT NOT NULL,
  notes        TEXT,
  created_at   TEXT NOT NULL,
  updated_at   TEXT NOT NULL
);
CREATE INDEX ix_ss_cat_date ON selfcare_session(category_key, local_date);

CREATE TABLE selfcare_session_type (
  session_id INTEGER NOT NULL REFERENCES selfcare_session(id) ON DELETE CASCADE,
  type_key   TEXT NOT NULL,
  type_name  TEXT NOT NULL,         -- snapshot
  PRIMARY KEY (session_id, type_key)
);
CREATE INDEX ix_sst_type ON selfcare_session_type(type_key);

CREATE TABLE preferences (key TEXT PRIMARY KEY, value TEXT NOT NULL, updated_at TEXT NOT NULL);
CREATE TABLE schema_migrations (version INTEGER PRIMARY KEY, name TEXT NOT NULL, applied_at TEXT NOT NULL);
```

Connection settings: WAL, `foreign_keys=ON`, `synchronous=NORMAL`,
`busy_timeout`. Multiple sessions per day are allowed for both kinds.

These shapes support the future analysis slices directly: per exercise
(`exercise_key`), per muscle group (`workout_exercise_group`), per metric
(sum/max of `distance_m`, `weight_kg`…), per skincare type (`type_key`) and
category (`category_key`), all over `local_date`.

## 5. Backend behaviour

### `clock.py`
- `now()` UTC; `today()` = local date in `timezone`, minus `day_start_hour`.
- `local_date_of(ts)` applies the same rule. Every date decision in the app
  goes through these.

### `units.py`
- Fields map to storage units: weight → kg, distance → m, duration → s,
  reps → count.
- Converts to/from the user's `weight_unit` / `distance_unit` preference.
  Durations are displayed `h:mm:ss` / `mm:ss`.

### `workouts.py`
| Operation | Rules |
|---|---|
| `start(planned_exercises=[])` | Fails (409) if a workout is open. Creates `workout` with `started_at=now`, `local_date=today`. Each planned key is added as below with `planned=1`. |
| `add_exercise(workout, key)` | Key must exist in the catalog. Snapshots name, metric type, groups. Creates prefilled sets. |
| `prefill_sets(key)` | From the most recent **finished** workout containing `key`: its **done** sets in order, copied as new **undone** sets with the same values. If none: one empty undone set. |
| `add_set(we)` | New undone set copying the previous set's values (or empty). |
| `update_set(id, …)` | Only fields in the exercise's metric type are accepted (else 422). Values validated (non-negative, bounded). Allowed while the workout is open. |
| `toggle_done` | Via `update_set(done=…)`. Un-done is always allowed. |
| `delete_set`, `delete_exercise` | Only while open. |
| `finish(id)` | Transaction: set `ended_at=now`; delete undone sets; delete exercises with no sets. A workout left with no exercises is deleted and the caller told so. Emits `workout.finished`. |
| `reopen(id)` | Clears `ended_at` so it can be edited; 409 if another workout is open. `started_at`/`local_date` unchanged. Finishing again sets a new `ended_at`. |
| `discard(id)` / `delete(id)` | Removes the workout and children. |
| `focus(workout)` | Distinct muscle groups of its exercises, in first-appearance order. |
| `history(range)` | Finished workouts with `local_date` within the last 1W / 1M / 1Y, newest first: date, duration, focus, exercise count, set count. |
| stale check | An open workout older than `stale_workout_hours` is flagged `stale: true` on `GET /workouts/open`. |

"Duration" is `ended_at − started_at`; for a reopened-then-finished workout
it uses the original `started_at` and the latest `ended_at` (MVP
simplification; see §10).

### `selfcare.py`
- `log(category, types[], date?, notes?)`: at least one type; each must belong
  to the category. `date` defaults to today; `performed_at` = now when date
  is today, otherwise noon local on that date. Emits `selfcare.logged`.
- `update`, `delete`: any session, any time.
- `last_done(type)` = max `local_date` of sessions including that type.
- `due_list(today)` for each type with `every_days = N`:
  - never done → status `never`
  - `next_due = last_done + N`, `days_over = today − next_due`
  - `ratio = (today − last_done) / N`
  - status: `ok` (ratio < 0.8), `soon` (0.8 ≤ ratio < 1), `due` (today =
    next_due), `overdue` (days_over > 0)
  - sorted by ratio descending; types without `every_days` listed after,
    with last done only.

### `calendar.py`
- `entries(from, to, kinds)` → per `local_date`: list of
  `{kind, id, title, summary}`:
  - workout: title = focus (e.g. "Chest · Back"), summary = "5 exercises ·
    52 min"; open workouts included, marked `in_progress`.
  - selfcare: title = category name, summary = type names.
- `last_done()` → most recent `local_date` per kind and per self-care type.

### `catalog.py`
- Loads and validates the three YAML files at startup; exposes lookups
  (exercise by key, grouped by muscle group; types by category; colors).
- Errors collected for `/api/health`, never raised to crash the server.

### `metrics.py`
- Exists with a module docstring describing its future role (e1RM, PRs,
  volume, distance totals as pure functions over stored sets). No
  calculations in the MVP.

### Preferences
- `preferences` rows seeded from `settings_defaults` on first run (Hermes
  pattern); afterwards the database is authoritative. Keys and allowed values
  are validated against the same enums as the YAML.

## 6. API (`/api`)

| Method & path | Purpose |
|---|---|
| `GET /health` | status, config errors, DB status |
| `GET /catalog` | metric types, exercises grouped by muscle group, self-care categories and types, kind colors |
| `GET /settings` · `PUT /settings/{key}` | preferences |
| `POST /workouts` `{planned_exercises?: [key]}` | start (409 if one is open) |
| `GET /workouts/open` | the open workout (full detail, `stale` flag) or `null` |
| `GET /workouts?range=1W\|1M\|1Y` | finished workout summaries |
| `GET /workouts/{id}` | full detail |
| `POST /workouts/{id}/exercises` `{exercise_key}` | add exercise with prefilled sets |
| `DELETE /workouts/{id}/exercises/{we_id}` | remove exercise |
| `POST /workouts/{id}/exercises/{we_id}/sets` | add set |
| `PATCH /sets/{id}` `{weight?, reps?, distance?, duration?, done?}` | edit / tick a set |
| `DELETE /sets/{id}` | remove set |
| `POST /workouts/{id}/finish` · `/reopen` | lifecycle |
| `DELETE /workouts/{id}` | discard or delete |
| `POST /selfcare/sessions` `{category, types, date?, notes?}` | log |
| `GET /selfcare/sessions?range=&category=` | history |
| `GET · PATCH · DELETE /selfcare/sessions/{id}` | detail, edit, delete |
| `GET /selfcare/due` | due list |
| `GET /calendar?from=&to=&kinds=` | per-day summaries |
| `GET /calendar/last-done` | last done per kind and per type |

- Values cross the API in the user's **display units**; the backend converts.
- Errors: `409` conflict (second open workout, editing a finished workout
  without reopening), `422` invalid field for the metric type or bad value,
  `404` missing. Bodies carry a human-readable `detail`.
- OpenAPI docs at `/docs` (the future Claude integration's contract).

## 7. Frontend

### Platform

Phone-first (designed at ~390 px, scales up), iPhone Safari primary:
- In-app back button on every sub-screen (standalone "Add to Home Screen"
  mode has no browser back).
- Safe-area insets for notch and home indicator (Hestia's tokens).
- `inputmode="decimal"`/`numeric` and ≥ 16 px inputs (no zoom-on-focus).
- Timers derived from stored start timestamps (iOS suspends timers when
  locked).
- No haptics dependency (Vibration API unsupported on iOS); no offline mode
  (LAN http).

### Navigation and routes

Bottom tab bar on phones, top on desktop: **Calendar · Workouts ·
Self-care · Settings**. Hash routing so Safari back/swipe, bookmarks and deep
links work; the server always serves `index.html` at `/ui/`.

```
#/calendar?view=week|month|year&kind=all|workout|selfcare   landing
#/calendar/day/YYYY-MM-DD
#/workouts                   hub
#/workouts/active            logging (new, resumed, or reopened)
#/workouts/history?range=…
#/workouts/{id}              read-only detail  [Edit] [Delete]
#/selfcare                   hub
#/selfcare/log · #/selfcare/log/{id}
#/selfcare/history?range=…
#/selfcare/{id}
#/settings
```

### Screens

**Calendar (landing)**
- "Last done" strip: e.g. "Workout · 2 days ago   Skincare · today".
- View switcher (week / month / year; default from Settings), prev/next,
  kind filter (all / workout / self-care).
- Week: 7 day rows with entry titles. Month: grid with a coloured dot per
  entry (max 3 + "+n"). Year: vertical heatmap — 7 columns (weekdays) ×
  ~53 week rows, newest at top, month labels in the margin; with kind=all
  each cell is split (left workout, right self-care), each half shaded by
  that day's count; with a single kind the cell is solid.
- Tap a day → day view with its entries → tap an entry → its detail.

**Workouts hub**
- Resume banner when a workout is open (stale variant offers Finish /
  Discard / Keep going).
- **Start workout** → `#/workouts/active`.
- Compact month calendar (workouts only); tap → `#/calendar?kind=workout`.
- **Past workouts** → history.
- **Stats** card: "Coming soon".

**Active workout**
- Header: elapsed time; menu with Discard.
- Exercise cards in order; each shows its sets as `SetRow`s and "+ Add set".
- Undone sets render muted; ✓ marks done (saved immediately); tap ✓ again
  to undo; done values stay editable.
- "+ Add exercise" → `ExercisePicker` bottom sheet: grouped by muscle group,
  search, recently used first.
- **Finish** → summary sheet (exercises, done sets, duration; note that
  unticked sets will be dropped) → confirm.
- The same screen edits a reopened workout; its button reads **Save**.

**Workout history / detail**
- `RangeFilter` (1W / 1M / 1Y, default from Settings), list of
  `SessionCard`s (date, duration, focus chips, exercise count), scrollable.
- Detail: exercises with their sets, notes; **Edit** (bottom) reopens into
  the active screen; **Delete** with confirmation.

**Self-care hub**
- **Log skincare** → log screen.
- **Due** list: coloured status dot, type, "3 days ago" / "due in 2" /
  "4 days overdue" / "never".
- Compact calendar (self-care only); tap → `#/calendar?kind=selfcare`.
- **Past sessions** → history.

**Log / edit skincare**
- Date (default today), type chips toggled on/off (due and overdue types
  pre-highlighted, not pre-selected), note, Save. Edit mode adds Delete.

**Self-care history / detail**: as for workouts, with type chips.

**Settings**: default calendar view, week start, weight unit, distance unit,
default history range — saved on change. Shows config errors, if any.

### Components

`Calendar` (props: `view`, `kinds`, `compact`, `anchorDate`; renders week,
month, year-heatmap and compact variants) · `SessionCard` · `ExercisePicker`
· `SetRow` (fields driven by metric type: weight/reps steppers, distance
decimal input, duration mm:ss with optional start/stop timer) ·
`RangeFilter` · `Toast` · `ConfirmSheet` · `BackBar` · `TabBar` · `Icon`
(inline SVG sprite from Lucide, MIT).

### State and data

- `api.ts`: typed fetch wrapper; types in `types.ts` mirror `schemas/`.
- Set edits are optimistic: the UI updates immediately, then PATCHes; on
  failure it reverts and shows a toast.
- Catalog and settings fetched once at boot and on change.

### Styling and motion

- `tokens.css` keeps Hestia's token names unchanged, adds
  `--color-workout` / `--color-selfcare` (from `apollo.yaml` via
  `/api/catalog`), and defines light and dark palettes (dark default).
- Push/pop slide transitions between screens (View Transitions where
  available, iOS 18+; Svelte transitions otherwise); ✓ fill animation;
  exercise cards animate in; sheets slide up. All motion disabled under
  `prefers-reduced-motion`.

## 8. Error handling

- **Config errors:** reported with file and entry at `/api/health` and in
  Settings; the server stays up; affected screens show an inline notice.
- **API errors:** 409 / 422 / 404 with readable `detail`, surfaced as toasts;
  optimistic edits roll back.
- **Stale open workout:** flagged, user chooses Finish (ended at the last
  set's update time), Discard, or Keep going.
- **Catalog edits vs history:** removed or renamed exercises and types
  never break history (snapshots); removed ones disappear from pickers only.

## 9. Testing

**pytest**
- Config: valid files; unknown keys; duplicate keys; undefined type/group;
  `group` vs `groups`; bad `every_days`.
- Clock: day-start hour boundary; timezone; DST edge.
- Units: round-trip kg↔lb, m↔km/mi, duration parsing/formatting.
- Workout lifecycle: start; 409 on second open; add exercise; prefill from
  the last finished workout (done sets only, set by set); add set; field
  validation per metric type (422); toggle done/undone; finish drops undone
  sets and empty exercises; empty workout deleted; reopen / 409; delete.
- Focus and history ranges.
- Self-care: log/edit/delete; due statuses (never, ok, soon, due, overdue);
  sort order; types without `every_days`.
- Calendar: merge of both kinds, multiple sessions per day, in-progress
  workout, kind filter, last-done.
- Every API route (status codes, unit conversion at the edge).

**vitest**: date/duration formatting, route parsing.

**Manual acceptance** (before calling the MVP done): `make build run`; on a
phone-sized viewport and on the iPhone — log a workout with a weight
exercise, a run and a plank; finish; view it in history and on all three
calendar views; edit and re-save it; log two skincare sessions; check the
due list; change Settings and confirm the calendar default follows.

## 11. Decisions log

| Decision | Choice |
|---|---|
| Skincare input | Types from a configured list per session (+ date, note) |
| Skincare due tracking | Optional `every_days` per type; due list computed |
| Workout focus | Derived from exercises' muscle groups |
| Claude-ready | `start(planned_exercises)` hook, `planned` flag |
| Page structure | Tab hubs with buttons; sub-screens with back buttons |
| Year view | Vertical heatmap, split cells for two kinds |
| Exercise fields | Reusable metric types over four built-in fields |
| Prefill | From the last finished session, set by set |
| Logging a set | Per-set ✓, reversible; only done sets count |
| Past workouts | Read-only detail with Edit (reopen) and Delete |
| Config | Three committed YAML files in `config/` |
| Settings | Settings tab stored in DB, seeded from `apollo.yaml` |
| Frontend | Svelte 5 + Vite + TS, hash routing, served at `/ui/` |
| Storage | Separate tables per kind; SI units; snapshots; nothing derived stored |
